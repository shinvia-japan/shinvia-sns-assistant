# Shinvia SNS投稿アシスタント

Instagram・Threads・楽天ROOM向けの投稿文案を作成する、日本語の試作品です。AI生成の利用条件・料金は接続先の管理者に確認してください。青と白の画面で、テーマ入力 → 文案作成 → 編集 → 保存・コピーができます。

## 初めての起動

1. [Node.js](https://nodejs.org/ja) のLTS版（Node.js 20以上）をインストールします。
2. GitHubの「Code」→「Download ZIP」でダウンロードして展開するか、次のコマンドで取得します。
   ```sh
   git clone https://github.com/shinvia-japan/shinvia-sns-assistant.git
   cd shinvia-sns-assistant
   ```
3. 展開した `shinvia-sns-assistant` フォルダでターミナルを開き、次を実行します。
   ```sh
   npm start
   ```
   追加パッケージのインストールは不要です。AI生成には管理者から案内された認証トークンとインターネット接続が必要です。トークンは生成時に入力し、保存しません。AIプロバイダーのAPIキーはブラウザに入力しないでください。
4. ブラウザのアドレス欄に `http://localhost:3000` を入力します。
5. 終了するときはターミナルで `Ctrl+C` を押します。次回も同じフォルダで `npm start` を実行します。

「node / npm が見つからない」場合はNode.jsをインストールし、ターミナルを開き直してください。ポートが使用中の場合は既存のサーバーを終了するか、macOS/Linuxでは `PORT=3001 npm start`、PowerShellでは `$env:PORT=3001; npm start` を使い、3001番のURLを開いてください。

## 使い方

1. 投稿先のSNSを選びます。
2. 投稿テーマを入力します。「試してみる」の例も使えます。
3. 必要なら伝えたいポイントと文章の雰囲気を指定します。
4. 「投稿文案を作成する」を押し、右側（スマートフォンでは下側）の文章を編集します。
5. 「保存する」でこのブラウザに保存します。「保存した投稿」から開き直して上書きできます。
6. 「コピーする」を押してSNSの投稿画面に貼り付けます。自動コピーが使えない場合は選択された文章を手動コピーしてください。

## 試作品の範囲

- AI生成時はCloudflare Worker経由で外部AIサービスに接続し、テーマ・投稿先・補足情報・文章の雰囲気・生成指示を送信します。個人情報や患者情報は入力しないでください。保存済みの投稿一覧は送信しません。
- Instagramは1枚完結・約9秒のリール用の6項目を見出しで分けて表示します。画像・動画自体は生成しません。Threadsは薬剤師の日常の短いつぶやき、楽天ROOMは入力された特徴をもとに使用経験を捏造しない紹介を指示します。
- 医薬品・健康情報は誇張を避けるようAIに指示しますが、正確性や出典の確認を自動で保証する仕組みはありません。投稿前に公的資料・添付文書で確認してください。
- Workerが生成指示をAIに渡していることが前提です。仕様と確認事項は [Worker側の対応事項](WORKER_REQUIREMENTS.md) を参照してください。
- 楽天ROOMでは商品取得や価格確認をしません。実際の体験、商品情報、広告・PRの表示などは投稿前に自身で確認してください。
- 保存はブラウザのlocalStorageです。アカウント、クラウド同期、画像アップロード、SNSへの自動投稿はありません。
- 保存内容は端末・ブラウザ・接続先URLごとに異なります。ブラウザデータ削除やプライベートモード終了で失われる場合があります。大切な文章は別途保管してください。機密情報の保存は避けてください。
- 公開運用用の認証・バックアップは未実装です。開発サーバーは初期設定で端末内からのみアクセスできます。

## 開発と確認

```sh
npm test
npm start
```

`npm test` は媒体別指示、Instagramの6項目とハッシュタグ制限、Markdown除去、通信エラー・タイムアウト、失敗時の文案保持、連続送信抑止、保存・コピー、従来のテンプレートと保存データ読み取りを確認します。外部AIの実通信は行わず、模擬応答を使用します。画面では、3媒体での作成・編集・保存・再読み込み・コピー・削除を確認してください。

構成：`index.html`（画面）、`style.css`（見た目）、`app.js`（操作・保存）、`generator.js`（文案）、`server.js`（開発サーバー）。依存パッケージはありません。

## GitHubへの保存

Web画面の「保存する」は投稿文のブラウザ保存であり、GitHubへの保存ではありません。コードを変更したら、リポジトリのフォルダで以下を実行します。

```sh
git switch -c feature/my-change
git add .
git commit -m "Update Shinvia SNS assistant"
git push -u origin feature/my-change
```

GitHubの画面でPull Requestを作成し、確認後にmainへ取り込みます。pushにはリポジトリの書き込み権限が必要です。認証情報をコードに書かないでください。

## WindowsのChromeから使う：GitHub Pagesで無料公開

このアプリはサーバー側の処理が不要なため、GitHub Pagesで公開できます。公開後はPCへのNode.jsインストールや、Codexでのサーバー起動は不要です。静的サイトの公開にはAPIキー、独自ドメイン、有料契約は不要です。ただし、AI生成は別のWorkerサービスを使用するため、その利用料金・上限・認証は管理者に確認してください。

GitHub Freeでは公開（Public）リポジトリでGitHub Pagesを使えます。PrivateリポジトリでPagesを使う場合はプラン条件が異なります。Privateの場合はここで止まり、公開してよいコードかを確認してください。この手順では可視性の変更や有料プランの契約は行いません。Pagesは一般公開されるWebサイトです。アプリにログイン制限はありません。

### 初回設定（リポジトリの管理権限がある方）

1. GitHubで公開対応用の `feature/github-pages` ブランチから `main` へのPull Requestを作り、差分を確認してマージします。すでにマージ済みなら不要です。
2. リポジトリ上部の **Settings** を開きます。個人アカウントの設定ではなく、このリポジトリの設定です。
3. 左側の **Pages** を選びます。
4. **Build and deployment** → **Source** で **GitHub Actions** を選びます。サンプルワークフローを追加する必要はありません。本リポジトリに `.github/workflows/pages.yml` を用意しています。
5. リポジトリ上部の **Actions** → **Publish Shinvia to GitHub Pages** を開きます。Actionsが無効な場合は、組織の方針を確認し、このリポジトリのActionsを有効にします。
6. **Run workflow** を押し、ブランチが **main** であることを確認して、緑の **Run workflow** を押します。先に自動実行が失敗していても、PagesのSource設定後にここから実行できます。
7. `build` と `deploy` が緑色になるまで待ちます。失敗した場合は赤い項目を開きます。`build` はテスト、`deploy` はPagesのSource・公開条件・権限を確認してください。有料契約は行わず、エラー内容を確認してください。
8. **Settings → Pages** に表示された公開URLをWindowsのChromeで開きます。標準の想定URLは `https://shinvia-japan.github.io/shinvia-sns-assistant/` です。独自ドメイン等がある場合はGitHubが表示する実際のURLを使ってください。
9. SNSを選び、テーマ入力 → 文案作成 → 編集 → 保存 → コピーを試します。再読み込み後も保存した投稿が表示されることを確認します。
10. Chromeのアドレス欄右側の星マークでブックマークします。次回からそのURLを開くだけで使えます。

初回公開直後に404になる場合は、Actionsの成功とPagesのURLを確認し、数分待って再読み込みしてください。URL末尾の `/shinvia-sns-assistant/` を省略しないでください。

### 公開後の注意

- ワークフローは `main` の更新時にも自動実行されます。テスト成功後に画面用の4ファイルだけを公開し、`.git`・テスト・開発サーバーは配信しません。
- JavaScript、画面、CSSは閲覧者から見えます。認証情報や秘密の情報をコードに追加しないでください。
- 保存した投稿文は各利用者のChrome内にだけ保存され、GitHubに送られません。AI生成時の入力内容は外部サービスに送信されます。他の端末や別のURLには引き継がれません。localhostで保存した投稿も公開URLには自動移行しません。必要な文章はコピーして移してください。
- HTTPS上ではコピーボタンが使えます。Chromeの権限等で失敗した場合は、選択された文をCtrl+Cでコピーしてください。
- サイトを非公開にするには **Settings → Pages → Unpublish site** を使います。再公開を防ぐにはワークフローも無効にします。
- GitHub Pages・Actionsの無料利用にはGitHub所定の条件や上限があります。この小規模な静的試作品は無料枠での利用を想定しています。GitHubの画面に課金やプラン変更が表示されたら進めずに確認してください。
